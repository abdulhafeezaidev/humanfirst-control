# Pilot Admin Setup Checklist

## Pre-Pilot (Before Day 1)

### Account Setup
- [ ] Institution account created in system
- [ ] Organization name and slug configured
- [ ] Pilot expiration date set (10 weeks from start)
- [ ] Primary admin account created (Owner role)
- [ ] Admin received welcome email with login credentials

### Technical Preparation
- [ ] Pilot feature flags enabled for organization
- [ ] Usage limits configured per pilot tier
- [ ] Audit log retention set to 30 days
- [ ] Tamper event retention set to 14 days
- [ ] Pilot analytics dashboard accessible

### Documentation Shared
- [ ] Admin training materials sent
- [ ] Student transparency FAQ prepared
- [ ] IT security overview document provided
- [ ] Ethics charter and privacy policy shared

---

## Week 1: Kickoff

### Day 1-2: Admin Onboarding
- [ ] Admin logs into dashboard for first time
- [ ] Admin completes profile setup
- [ ] Admin reviews organization settings
- [ ] Kickoff call scheduled and completed

### Day 3-5: Training
- [ ] Admin completes "Platform Overview" module
- [ ] Admin completes "Creating Your First Policy" module
- [ ] Admin completes "Understanding Tamper Events" module
- [ ] Admin completes "Student Transparency" module
- [ ] Admin creates first test policy (draft mode)

### Day 5-7: Device Registration
- [ ] First admin device registered
- [ ] Test enforcement run on admin device
- [ ] Confirm tamper detection working
- [ ] Second admin invited (if applicable)

---

## Week 2-3: Ramp-Up

### Student Enrollment
- [ ] First 10 students enrolled
- [ ] Students receive transparency onboarding
- [ ] Student consent flow completed (if required)
- [ ] Device registration instructions distributed

### First Live Policy
- [ ] First exam/focus policy created
- [ ] Policy assigned to student group
- [ ] Policy scheduled for specific time window
- [ ] Admin notified of policy activation
- [ ] Post-policy metrics reviewed

### Validation
- [ ] Confirm enforcement active during policy window
- [ ] Confirm student transparency view working
- [ ] Confirm tamper events logged correctly
- [ ] Confirm audit trail complete
- [ ] Address any early issues

---

## Week 4-8: Full Pilot

### Weekly Checks
- [ ] Review weekly metrics report
- [ ] Check compliance rate trends
- [ ] Review any tamper events
- [ ] Log admin engagement frequency
- [ ] Document feedback or concerns

### Expansion Activities
- [ ] Expand to additional student cohorts
- [ ] Create additional policy types (Focus mode)
- [ ] Test policy conflict resolution
- [ ] Invite additional admin (if needed)
- [ ] Share policies with other admins (if applicable)

### Stakeholder Engagement
- [ ] IT/Security team briefed on system
- [ ] Compliance officer review completed
- [ ] Student feedback collected (optional)
- [ ] Mid-pilot review meeting held (Week 4)

---

## Week 9-10: Evaluation

### Metrics Compilation
- [ ] Export compliance report (PDF)
- [ ] Calculate final health score
- [ ] Document success criteria achievements
- [ ] Prepare metrics summary for stakeholders

### Decision Meeting Prep
- [ ] Schedule decision meeting with stakeholders
- [ ] Prepare upgrade proposal (if applicable)
- [ ] Document any outstanding concerns
- [ ] Prepare pricing and plan options

### Outcome Documentation
- [ ] Record final decision: Upgrade / Extend / Discontinue
- [ ] If upgrading: Initiate plan upgrade process
- [ ] If extending: Document extension terms
- [ ] If discontinuing: Initiate offboarding process

---

## Post-Pilot Actions

### If Upgrading
- [ ] Upgrade plan type in system
- [ ] Extend usage limits
- [ ] Enable premium features
- [ ] Migrate to production retention policies
- [ ] Schedule expanded rollout plan
- [ ] Confirm pricing locked

### If Extending
- [ ] Set new expiration date (max +4 weeks)
- [ ] Document specific goals for extension
- [ ] Schedule weekly check-ins
- [ ] Set hard decision deadline

### If Discontinuing
- [ ] Export final compliance reports
- [ ] Disable all enforcement
- [ ] Notify affected students
- [ ] Begin 30-day data retention countdown
- [ ] Conduct exit interview
- [ ] Archive lessons learned

---

## Emergency Procedures

### If Enforcement Fails During Exam
1. [ ] Check system status page
2. [ ] Verify network connectivity
3. [ ] Contact support (L2 escalation)
4. [ ] Document incident for audit
5. [ ] Notify affected students/faculty

### If Privacy Concern Raised
1. [ ] Acknowledge concern immediately
2. [ ] Review specific data access in audit logs
3. [ ] Prepare transparency report
4. [ ] Schedule call with concerned party
5. [ ] Escalate to Customer Success if unresolved

### If Usage Limit Reached
1. [ ] Review current usage in dashboard
2. [ ] Identify if limit is blocking critical operations
3. [ ] Request temporary limit extension (support ticket)
4. [ ] Discuss upgrade options with Account Manager
